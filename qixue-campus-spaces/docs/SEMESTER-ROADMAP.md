# 从每周教室查询到时间、日程与校园路径推荐

日期：2026-10-18，时区 Asia/Shanghai。

## 先区分三种数据

1. **学校教室占用课表**：决定一间教室某节有没有课程、考试、借用或屏蔽。用户不参加课程也不能改变这份记录。
2. **个人本学期课程表**：决定用户通常需要到何处上课。这是个人资料，需用户明确授权读取、导入和本机保存；不能混入公共场所数据或 Git。
3. **个人动态日程与单次例外**：临时会议、办事、提前结束、取消或“本次不参加”。只覆盖具体发生的一次事项，不改官方课程或同一课程以后的安排。

“最优”指在已知资料、用户当前选择和已核实约束下最合适，不承诺绝对最优、实时有座或允许使用未知设施。

## 已执行与当前限制

- 官方教室查询已真实取得423个教室、17,766个节次状态。当前页面周次控件只实际观察到第5、6周；没有证据证明当前入口支持一次下载全学期，不拼接不存在的周次、不绕过限制。
- 本周缓存改为同周复用，最长采集后7天且不跨上海周一零点；主动刷新仍可发现临时调课。缓存不是实时座位。
- 网页显示本机系统时间（固定上海时区），提供“从现在开始”，不是联网校时或学校服务器时间。
- 0.5版可以手动录入具体日期的课程或其他事务、只对本次设置不参加 / 恢复参加，并检查学习钟点时段与这些已录入事项的冲突。预留分钟由用户设置，不假装是地图算出的步行时间。
- 个人官方课表导入、全学期教室批量抓取、节次钟点表与路线均尚未实现。当前个人日程按具体日期保存；重复课程、调课和节假日规则待正式导入模块接入。
- 本轮已实际通过67项规则/接口测试和22组浏览器检查；包含周缓存、推荐按钮、系统时钟与动态日程冲突。这些检查不替代尚未取得的官方学期数据、节次时间和地图路线验证。
- 已实际核对清华官方校园地图页面，HTTP 200，标题“校园地图-清华大学”：https://www.tsinghua.edu.cn/zjqh/xyfg/xydt.htm 。这仅证明地图页面存在，不代表已获坐标、路线数据或地图素材转载许可。作品目前只提供官方链接。

## 路径一：按最少依赖逐步接入（建议）

### 第一步：时间基准与今天能用的窗口

- 本机当前时间转换成 Asia/Shanghai 显示；页面跨午夜重新检查日期和缓存，不静默改变用户手动选定日期。
- 核实学校最新作息表：必须确认官方教室页第1–6“节”是大节还是小节，并取得每一节的真实开始、结束时间、适用日期、特殊作息。不能把别校或旧学年的时间硬编码成当前事实。
- 保存 `academic-calendar.json`（学期id、正式起止日期、周次基准、单双周、停课/补课日、来源与核实时间）与 `bell-times.json`（节次、开始/结束、适用日期、来源）。未核实保持未知，不做自动时间映射。
- 推荐开始时刻为 `max(当前时刻, 用户计划开始, 用户到达候选地点时刻)`。扣除下一个需参加事务的到达预留，计算实际可学习分钟。

验收：午夜、跨周、当前已上课、课间、节假日、同日临时办事和取消事项均有明确行为；没有日程记录不等于用户没有课。

### 第二步：个人学期课表入站

优先顺序：

1. **校方正式允许的数据接口或导出**（如果存在、且获许可）：导入 JSON / CSV / ICS，保留原始来源、导入时刻和适用学期。官方导出也是本机处理，无需数据库或额外付费模型。
2. **认证窗口的只读个人课表适配器**：用户在官方窗口完成认证后，单独定位“个人课程表”真实页面，核实字段与系统限制，只读必要课程名称、地点、起止、周次和例外；不采集成绩、通讯录、消息。当前尚未定位和验证该页面。
3. **用户官方文件导入**作为故障回退：接口变化或验证码出现就暂停自动同步，不无限重试，保留上次版本和明确的过期状态。

不要使用未公开、猜测出来的隐藏接口；“用户能访问”与“允许大范围公开分发”是两件事。

本机文件建议分开：

```text
data/private/semester-courses.json     个人学期课程（不入Git）
data/private/agenda-overrides.json     单次参加状态、取消、挪动（不入Git）
data/private/agenda-events.json        临时事务（不入Git）
data/private/classrooms/<term>/<week>.json  各周教室占用快照（不入Git）
```

若个人日程在前端使用，可用当前浏览器 IndexedDB 保存；初版手动日程已在 localStorage，后续需提供迁移、导出和清除。服务器文件与浏览器缓存不能靠无验证的双写维持一致。只保留必需字段，绝不把密码、Cookie 或 SSO ticket 存入课表。

### 第三步：动态日程覆盖层

- 每门课程有稳定 `courseId`；每一次实际发生的课有 `occurrenceId = courseId + 原始日期/开始时间`。
- `attending / skip_once / cancelled / moved` 以 occurrence 为键。只修改用户个人安排，不改教室占用，不自动替用户决定缺席。
- “今天不参加”与“以后都不参加”必须分开；默认仅本次。取消例外即恢复原始课程安排。
- 临时事务有起止、地点、硬性/可调整标志，支持冲突提示。含用户姓名的日程标题不发送到外部地图或模型。
- 同步时做差异合并，保留用户例外；官方改时间后标记需用户复核的旧例外，不能静默套在另一节课上。

### 第四步：整学期的教室资源

- 不要求第一天拿到所有周。按官方能查询的周次保存独立快照，优先本周、下周；逐步累积“本学期已取得范围”。
- 只有官方提供全学期查询/导出且允许时才完整同步。请求串行、显示进度、可取消、不频繁刷，出现认证、限流或错误即停止。
- 缓存键含 `termId + weekStart + 查询范围/教室管理类型`，不能用一个小范围查询覆盖整校全量快照而假装完整。
- 已知未来周的排课可以预存，但到那一周时需按新鲜度政策复核；不能因为学期文件存在就一直称作最新。
- 个性化推荐取个人空闲窗与教室可用窗的交集；没有自习准入证据时结果仍为“课表条件候选”，不能升级为“确认可用”。

## 地图的三种路线

| 方案 | 首期能力 | 代价与边界 |
| --- | --- | --- |
| A. 建筑列表 + 官方地图链接 | 先核实楼名别名、下一堂课教学楼，用户手选起点 | 最快，无地图服务或Key；暂不提供准确步行分钟 |
| B. 本地二维校园地图 + 步行路网（建议） | 用有许可的底图/自行绘制SVG，核实主要建筑入口及真实道路；本地最短路 | 不需要付费模型；需人工核实道路、桥、门禁、坡道、施工，未核实的路不画成可通行 |
| C. 授权地图服务或校方地理接口 | 可取得底图、定位、路线时集成 | 先核对许可、收费、Key和坐标系；与“无需额外Key”的默认目标冲突时仅作可选方案 |

地图不是第一步的硬前提。先从少数实际推荐教学楼入手，使用已核实入口间的步行时间矩阵；不要靠教室名称的“二/三/六”自动猜建筑位置。

数据模型可用：

```text
buildings: id, officialName, verifiedAliases[], entrances[], source, verifiedAt
nodes: id, x/y或经纬度, 坐标系, buildingId, kind, verifiedAt
edges: from, to, lengthMeters, walkingAllowed, accessHours, stairs, verifiedAt
rooms: officialRoomId, buildingId, floor, evidence
```

- 同一地图内坐标系必须一致；未核实经纬度不放“精确位置”图钉。
- 用 Dijkstra / A* 在步行路网上求路；只有核实了道路长度和速度假设后才显示“估算步行分钟”，并注明楼内/电梯时间是否包含。
- 用户手动选起点作为默认；浏览器定位需明确授权，误差或不可用时回退，不强制实时追踪。
- 目的地不是建筑中心点，而是可进入的入口；下一项事务的教学楼同样约束出发时间。

## 推荐算法：先排除不能用，再解释排序

1. 建立个人当天需参加的课程和事务，应用单次例外，求出从当前时刻起的可学习窗口。
2. 对每个教室求窗：官方排课空闲 ∩ 已核实开放 / 准入 ∩ 用户需求。
3. 加入起点→教室、教室→下一事务的步行/楼内时间；`有效学习时长 = min(教室可用结束, 下一事务开始 - 返程时间 - 预留) - max(现在, 到达时刻)`。
4. 不足最低学习时长、与考试/事务冲突、时间未知或无准入依据的场所，排除或放入单独的待核实候选，不以“高分”掩盖硬约束。
5. 先用可解释的分层排序：能满足时长 → 需要供电等已核实设施 → 有效学习分钟更长 → 步行更短 → 变动风险更低。需要加权时权重由用户调整，不让模型虚构分值。
6. 每张卡显示：可学习区间、下一项事务、预计离开时间、路程假设、匹配/未核实项、信息来源、更新时间及为何排在前面。没有地图就不显示虚构的“步行3分钟”。

## 推荐实施顺序

1. **本轮已做**：同周缓存、可见的推荐结果、系统时间、具体日期的个人事项与单次不参加、冲突反馈。
2. **下一个数据关卡**：官方作息/校历和个人课表真实入口；先跑通今天完整链路，不宣称全学期已导入。
3. **轻地图**：少数主要教学楼+入口+核实步行连接，加入下一事务到达约束。
4. **学期同步**：支持的周次逐周快照、个人课表导入、差异同步、调课与例外合并。
5. **图书馆**：再核实公开座位页/接口；可公开访问不等于允许任意频率爬取。它是短期动态数据，不能沿用教室的一周缓存，应独立显示采集时间和过期规则。

## 当前不可承诺

没有实际完成的个人官方课表获取、学期批量查询、道路数据、实时位置和图书馆查询不标记“已接通”。在官方节次钟点和个人课程未核实前，系统时间只能用于个人手动日程冲突，不能可靠自动识别当前官方教室节次。
