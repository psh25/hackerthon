# 真实场所数据录入规范

## 本轮数据状态

目前已取得423个教室的真实官方课表，但自习许可、安静/讨论/供电等场景设施和图书馆资源尚未核实。因此 `data/places.json` 的 `places` 仍为空，**不能宣称已完成完整场景推荐的验收**。教室课表单独在页面展示并允许按日期/节次筛选，不把课表空闲当作自习许可。不从搜索引擎拼凑数据，也不将测试夹具当生产数据。动态认证连接与快照边界见 `docs/DYNAMIC.md`。

收到调查资料后：逐个核对官方链接和字段，填入真实校园名称，设置 `datasetStatus` 为 `verified`，按实际核实日期设置 `updatedAt`。不要把本次开发日期误当作场所核实日期。

## 数据结构

根对象字段：`schemaVersion: 1`、`campus`（校园名或 null）、`datasetStatus`（`awaiting_verified_data` / `verified`）、`updatedAt`（YYYY-MM-DD 或 null）、`notice`（数据限制说明）、`places`（场所数组）。

每个场所包括：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一小写字母、数字、连字符标识 |
| `name` | 已核实场所名称，不可为空 |
| `location` | 官方明确的地址 / 楼层 / 区域 |
| `openingHours` | 官方公布的常规开放时间；保留适用学期、日期等限定 |
| `access` | 官方确认的读者身份、预约、入馆限制 |
| `features.quiet` | 官方明确支持安静学习 |
| `features.groupDiscussion` | 官方明确允许讨论，不能仅因有桌椅就推断 |
| `features.shortStay` | 官方明确支持临时 / 短时学习，不能从开放时间间接推断 |
| `features.power` | 官方明确提供学习用电源，不能从 Wi-Fi 或电脑设施推断 |
| `sources` | 官方出处数组，至少一个 |

每项已核实事实格式为 `{ "value": "已核实文本或布尔值", "sourceIds": ["来源标识"], "verifiedAt": "实际核实日期" }`。文字字段必须为非空文本，设施字段必须为 true 或 false。**未知项直接使用 JSON null**。官方明确不支持才使用有证据的 false，不能将未提及等同于不支持。

每项来源：`id`（同场所内唯一）、`title`（官方页面标题）、`publisher`（发布机构）、`url`（官方 HTTPS 页面）、`official: true`（由录入人员确认）。程序仅验证结构和 URL 安全，**无法自动认定某链接是官方或确认页面内容属实**。每个事实的 `sourceIds` 必须引用该场所实际存在的来源。

## 严格信息边界

- 只有具备来源、核实日期且值为 true 的场景设施才参与推荐。
- 核实项较完整者排在前面，然后按中文名称排序；没有虚构匹配分数。
- 未核实位置、开放时间、预约要求统一显示“待核实”。
- 所有实时空位、当前开放状态、电源当前可用性一律显示“待核实”，不根据客户端时钟或常规时间推算。
- 官方来源在卡片和详情中均可打开；详情说明来源对应的具体字段。
- 测试中的 `synthetic`、`example.edu` 是合成夹具，服务器不会提供 `tests/` 文件，网页也不会加载它们。

录入后执行 `npm test` 和 `npm run check`，再按 `docs/ACCEPTANCE.md` 使用真实官方数据人工验收。
