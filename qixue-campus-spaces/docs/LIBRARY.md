# 图书馆公开座位信息 · 0.7.0

## 实际核实的来源

2026-10-18（上海）实际匿名 GET `https://seat.lib.tsinghua.edu.cn/home/web/f_second`，HTTP200，页面直接包含6个分馆卡片及“今日剩余X，总量Y”。未发送 Cookie、账号密码，未登录，未选座或预约。

6个分馆是北馆(李文正馆)、西馆(逸夫馆)、文科图书馆、法律图书馆、美术图书馆、金融图书馆。此名单来自页面实际卡片，不写死数量，不为数量加入其他场所。每个卡片的官方入口 `/home/web/seat/area/{id}` 也来自该页面。

同时检查了队友项目采用的公开区域树 `/api.php/v3areas`，实际返回133个节点，含 TotalCount/UnavailableSpace 等字段。但区域、楼层、停用/隐藏标志存在不同聚合口径；本版**不自行将整棵树相减汇总**，也不沿用未重新核实的“占用”定义。以用户指定公开页面已展示的分馆数字为准。后续楼层扩展应另行逐字段核实。

## 不能推导的结论

- “今日剩余”按原文展示，不能改称现场传感器空座、当前开放、立即可进入、预约一定成功。
- 官方页面未提供这些数字的更新时间。只显示本作品的**采集时间**，上游更新时间保持 null，不冒充官方授时。
- 开放时段、进入/预约条件、具体楼层、地图位置/路线、供电、安静程度与讨论许可待核实；不因馆名推断设施。
- 图书馆候选是剩余条件候选，不是设施场景完全匹配；完整场景资料仍由独立的数据校验处理。

## 获取与缓存

1. 后端只读固定HTTPS公开页面，8秒请求超时、1MB大小限制，不跟随重定向，不接受用户传入任意URL，不执行页面脚本。
2. 只有页面中实际出现官方分馆座位入口的卡片才解析。数字缺失、格式变更、重复ID、余量大于总量、登录页或空结果均拒绝，不补零、不截断成正常数字。
3. 首次页面加载和可见页面每60秒请求本地接口；后端跨标签合并请求，同一服务60秒共享缓存。手动刷新最短30秒，失败后30秒可重试；无人在查看时不运行后台持续爬取。
4. 图书馆采用120秒采集新鲜度上限且不能跨上海日期，不使用教室的一周缓存策略。失败保留原始采集时间和上次记录，立即撤下图书馆推荐；恢复后重新获取。
5. 清洗快照写入忽略的 `data/private/library-snapshot.json`，只保留卡片公开字段，不保存整个官网HTML、Cookie、凭证或会话。读缓存失败时重新获取，写入失败明确提示。
6. GET `/api/libraries/observation` 独立于教室认证；POST `/api/libraries/refresh` 同源且要求当前CSRF令牌、拒绝正文。不暴露缓存文件静态路径。

## 推荐

一次“按我的需求推荐”分别生成教室和图书馆候选，两者不共享认证状态、缓存有效期或失败状态。图书馆仅对今日且包含此刻的钟点学习窗口，筛选采集时剩余大于0的分馆，按剩余数量降序/ID稳定排序；不输出虚构匹配百分比。改变场景、时间、供电等需求先撤下旧候选；动态日程、单次例外和用户自设预留同样生效。

## 5项重要人工验收

1. 不登录教室门户、不安装查询组件的新副本也能展示图书馆卡片；逐项比对官网的馆名、剩余/总量和官方链接（注意两次读取之间数字可能变化）。
2. 点击“从现在开始”并提交需求，教室与图书馆独立给出候选/无数据原因；图书馆按剩余排序，0剩余不进入候选，未知设施仍标待核实。
3. 切换场景、供电需求或未来时间会撤下旧结果；未来时间不拿当前剩余当预测；录入冲突事务后两边推荐均暂停。
4. 手动刷新、网络失败、超过2分钟、跨日时，卡片保留历史标识且图书馆推荐撤下，教室周缓存不被删除；网络恢复后可重试。
5. 电脑/手机展开详情、打开官方来源可操作；不出现用户名密码输入、自动选座、后台预约或“保证有座”等承诺。

自动化回归使用合成数据；真实官网检查只证明公开页面可读取及当次字段可解析，不证明校园网络持续可用或官方预约验收成功。
