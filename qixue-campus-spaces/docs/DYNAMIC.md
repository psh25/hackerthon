# 动态版设计与当前实现边界

2026-10-18，目标从静态场所发现扩展为认证后动态资源 + 每日需求推荐。

## 0.4–0.5 当前规则（覆盖旧版10分钟缓存策略）

- **周缓存**：同一周内可直接使用此前采集数据，无需再次登录，最长采集后7天且不跨上海时区的下一个周一零点；查询范围不覆盖、结构损坏或跨周不继续使用。不会把“按周缓存”说成已证明学校只会每周变更；仍提示临时调课风险，可主动更新。
- **推荐按钮**：应用日期、官方起止节次，显示课表条件候选与原因，默认12条并可展开。缺少节次、无结果、读取失败、跨周或日程冲突均给出反馈。尚未核实钟点→官方第1–6节的对应关系，不自动换算。
- **个人日程**：本机系统时间按Asia/Shanghai显示；“从现在开始”填入日期时间。具体日期的课程或其他事务保存在浏览器localStorage，单次“不参加/恢复参加”、删除和清除不更改官方教室占用。日程前后预留分钟由用户设定，不是地图距离。没有记录不等于当天无课。
- **权限边界**：此前版本未读取个人课表；用户现已提出希望导入，下一步需定位并核实官方个人课表的真实页面与许可。本轮尚未获取个人官方课程，不因授权就声称已同步。
- **路线**：只提供已核实存在的清华官方地图链接，尚未构建路网，不显示未经核实的距离或步行分钟。完整可行路径见`docs/SEMESTER-ROADMAP.md`。

## 已实现

此段保留0.2基础连接范围；0.3新增的教室查询与快照规则以“0.3 教室真实页面接入进展”为准。

- 网页选择学习日期、开始时间、时长、主场景及额外供电偏好，偏好仅保存在本机 localStorage。时区为 Asia/Shanghai；当前只支持当日内时段。
- 以主场景权重 2、额外供电偏好权重 1 计算“已核实偏好覆盖率”。未知和明确不支持分别标注、均不计分；不把百分比解释为有座概率。没有已核实场所就不生成推荐。
- 本地 Node 服务启动**可见官方登录窗口**，使用隔离的临时浏览器上下文。用户直接在清华官方页面输入密码并完成短信等二次认证，作品不接收密码和验证码。
- 会话只在本次浏览器内存中保留，不导出 storageState、Cookie、截图、门户 HTML 或网络 HAR；断开或关闭窗口后清除，最长 45 分钟后自动断开。首次及每次会话失效后均可能需要重新认证，不能保证“只登录一次”。
- “断开”仅关闭本作品的浏览器上下文，不调用学校全局注销，也不影响用户在其他浏览器中的登录。
- 连接状态包括未连接、启动中、待用户认证、已进入门户、已关闭、失败。进入门户不等于拿到了教室 / 图书馆数据。
- 点击“我已完成认证 · 检查连接”仅检查登录状态并发现当前官方页面的资源入口，每次入口发现间隔至少 30 秒。只读取匹配资源标签的链接，不读取个人首页正文、消息、成绩或个人课表。带查询字符串、片段或疑似令牌的链接不回传。
- API 仅同源和本机访问，修改连接状态需短期内存令牌，不允许凭据请求正文，不支持任意 URL 代理。没有新增数据库或付费 API。

## 0.3 教室真实页面接入进展

本轮先按用户许可通过本机窗口截图和 Windows 离线 OCR 读取已打开的资源页，确定准确入口为 `https://zhjw.cic.tsinghua.edu.cn/pk.classroomctrl.do`。普通 Edge 未开放 CDP、辅助功能接口未返回页面正文，因此没有复制 Cookie、密码数据库或其他个人浏览器资料。

修复了旧逻辑会因跳转地址不在 HTTPS 白名单而主动关闭窗口的问题：现在仅暂停未核实页面读取并保留窗口。教务系统实际存在 HTTP 跳转；只读解析限于已观察到的准确教务主机，不将 HTTP 作为凭据输入入口，不忽略证书错误。

在作品独立的临时官方窗口完成认证后，已实际自动点击门户的“教室状况查看”，再点击官方唯一“查询”按钮，取得 **423 个教室，每个42个节次（7天×6节）**。完整读取首、中、尾，0 异常拒绝行、未截断。状态来自官方单元格 title（“空闲”或“...,有课”等），不是颜色猜测；图例存在复用颜色，不能仅凭颜色区分借用/已约等状态。

网页新增独立的“教室官方课表候选”区域，按每日日期和用户显式选择的节次筛选，可只看选定节次均标为空闲的教室；官方容量0转为待核实，不能当作实时空位。日期来自页面月日和星期交叉核验，仅在采集日±21天内唯一匹配时补全年份，不推算学期起始日或钟点课表。

本机历史快照只保存清洗后的场所名、公布容量、节次状态、日期和采集时间，在 `data/private/classroom-snapshot.json`，已忽略于 Git。没有保存 Cookie、用户身份、门户 HTML、HAR 或课程内容。重启后标注“历史快照”；采集超过本作品保守的10分钟展示窗口就停止展示候选（这是产品策略，不是校方数据有效期）。断开认证不会删除这份不含身份信息的历史快照。临时截图在完成 OCR 后删除。

“按官方当前条件自动查询”保留官方已选周次和过滤条件，由用户主动触发，至少30秒间隔。重新读取同一DOM不会刷新已有数据的采集时间；只有实际查询才记录 `queriedAt`。不会批量遍历或后台轮询教务；不会自动预约、借用或提交其他业务表单。读取结果是课表记录，不是自习许可。

## 当前未实现，不能声称完成

图书馆资源、自习许可、节次到钟点时间的对应表及按任意学习时间自动选择周次尚未核实，实时座位与后台自动刷新尚未接通。`dynamicDataReady` 保持 false，`lastResourceSync` 为 null（完整推荐所需资源未齐）；教室课表本身通过 `classroomStatus: schedule_observed`、独立 `observedAt` 与记录数量说明实际采集状态。不要把整体 false 理解为教室查询没有执行，也不要把课表采集等同完整推荐已实现。

此前一次临时登录在官方二次认证页停止。本次改为可见官方窗口后，实际状态已到 `authenticated`，并只读发现“教室状况查看”入口，但尚未取得资源表字段和查询流程。不要重复使用聊天里曾暴露的密码，不要发送验证码、Cookie 或会话令牌。

## 完成认证后的下一步

1. 用户在官方窗口进入教室查询、图书馆资源页，核实平台允许的访问方式、使用条款、字段和查询频率。没有确认前不猜接口、不批量遍历。
2. 对实际页面实现独立的只读 adapter；只采集场所标识、资源状态、适用日期 / 时间、限制、官方出处和采集时间，个人身份信息不入库。
3. 分开表示“课表无排课”“允许自习”“可预约”“实时空位”；前一项不能推出后一项。图书馆与教室分别维护同步状态，某来源失败不得假装两者都成功。
4. 用实际核实的时间含义做学习区间匹配，并为每条动态记录展示来源、采集时间、适用区间和来源特定的新鲜度策略；过期或同步失败不继续显示为当前可用。
5. 用户主动触发同步优先；只有核实访问许可和频率后才启用低频自动刷新，遇到验证码、登录失效、429 或访问限制即暂停并提示用户，不绕过认证。

## 启动和依赖

静态功能仍为零依赖。官方连接和浏览器测试需要已有 Playwright 及本机 Chrome / Edge。优先查找项目依赖，其次使用 `BUNDLED_NODE_MODULES` 指定的本机依赖。可用 `BROWSER_PATH` 指定浏览器。

```powershell
node server.mjs
```

浏览器访问 `http://127.0.0.1:4173`，点击“打开官方登录窗口”。窗口在运行服务的电脑弹出。本版是本机单用户原型：不适合直接部署成多用户远程网站，也不能在手机上运行同一登录自动化；手机响应式仅指网页布局。

若要面向多用户上线，应优先申请校方正式授权的 SSO / 数据接口，另行设计用户会话隔离、TLS、访问控制、数据许可和持久化策略，不能直接复用当前单会话原型。
