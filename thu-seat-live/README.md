# 清华大学图书馆 · 座位实时看板

实时采集 [清华大学图书馆座位管理系统](https://seat.lib.tsinghua.edu.cn/) 的座位占用情况，并以网页形式可视化展示。

> 数据来源：`https://seat.lib.tsinghua.edu.cn/api.php/v3areas`（公开、免登录的只读接口）
> 本项目只做**只读聚合与展示**，不含登录、选座、退座等任何写操作，也不会代替你执行任何操作。

---

## 快速开始

需要 Node.js 20 及以上（本机已验证 v24），**零第三方依赖**，无需 `npm install`。

```powershell
cd thu-seat-live
node server.js
```

然后浏览器打开 **<http://127.0.0.1:8787>**。

可选环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 监听端口 |
| `HOST` | `127.0.0.1` | 监听地址（局域网访问可设为 `0.0.0.0`） |
| `POLL_MS` | `30000` | 后端采集间隔（毫秒），最小 10000 |
| `HISTORY_MS` | `21600000` | 内存中保留的历史时长（默认 6 小时），趋势图使用 |

```powershell
$env:PORT=9000; node server.js      # 换端口启动
```

## 页面能看到什么

| 模块 | 内容 |
| --- | --- |
| **总览环图** | 全馆在座率、当前空座数、在座数、总座位数，以及近 1 小时在座人数变化 |
| **座位拥挤度分布** | 按楼层占用率把空座分成「空闲 / 较拥挤 / 基本满座」三段 |
| **分馆实时占用** | 5 个分馆按在座率排序，点击任意分馆 → 展开 **楼层 → 阅览区** 三级明细（含每个阅览区空座数） |
| **分馆对比** | 各分馆在座率横向条形对比 |
| **座位热力图** | 分馆 × 楼层网格，颜色越红越拥挤，鼠标悬停看详情 |
| **在座率趋势** | 近 6 小时曲线，可切换「全馆 / 单馆」，支持鼠标悬停查看任意时刻数值 |
| **运行状态** | 采集耗时、快照新鲜度、历史样本数、上游状态 |

页面每 30 秒自动刷新一次，右上角可暂停自动刷新或手动刷新。

## 它是怎么工作的

```
┌────────────────────┐   GET /api.php/v3areas (每 30s)
│  seat.lib.tsinghua │ ─────────────────────────────┐
│  .edu.cn           │                              │
└────────────────────┘                              ▼
                                            ┌───────────────┐
                                            │  server.js    │
                                            │  采集 + 聚合   │
                                            │  + 内存缓存    │
                                            │  + 历史采样    │
                                            └───────┬───────┘
                                                    │ GET /api/dashboard（读缓存，极轻）
                                                    ▼
                                            ┌───────────────┐
                                            │  浏览器看板    │
                                            └───────────────┘
```

关键点：

1. **一次请求拿到全站数据。** 上游 `v3areas`（不带 id）一次返回全部 133 个区域节点的
   `TotalCount`（总座位）与 `UnavailableSpace`（当前不可用座位），因此每轮采集只需 1 个请求，
   耗时约 0.4–1.5 秒。
2. **后台轮询 + 缓存。** 前端无论刷新多少次都只读后端缓存，不会放大对校方服务器的压力。
3. **字段口径。** 「在座」= `UnavailableSpace`（已选座、已预约、临时离开锁定）；
   「空座」= `TotalCount - UnavailableSpace`。
4. **楼层口径校正。** 楼层节点自带的 `TotalCount` 可能包含已停用区域。例如北馆二层楼层节点写 280，
   但下属 6 个阅览区里有 2 个 `isValid=0`，有效阅览区累加为 280 —— 与官网一致；
   本项目一律以 **有效叶子节点累加** 为准，并把差异记录在 `issues` 字段里便于核对。
5. **失败不丢数据。** 上游偶发超时/异常时保留上一次成功快照，标记 `stale`，页面顶部会变色提示。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 可视化看板页面 |
| GET | `/api/dashboard` | 最新快照 + 历史采样（前端主数据） |
| GET | `/api/status` | 健康检查：采集状态、成功/失败次数、最近错误 |
| POST | `/api/refresh` | 触发一次立即采集（前端「刷新」按钮） |

`/api/dashboard` 主要字段：

```jsonc
{
  "summary": { "total": 3030, "occupied": 1370, "available": 1660,
```

## 目录结构

```
thu-seat-live/
├── server.js              # HTTP 服务 + 后台轮询 + 缓存 + 历史采样
├── src/
│   ├── tsinghua.js        # 上游接口客户端（含超时、编码、错误封装）
│   └── aggregate.js       # 扁平区域树 → 分馆/楼层/阅览区 三级聚合
├── public/
│   ├── index.html         # 看板页面结构
│   └── assets/
│       ├── style.css      # 深色主题样式
│       └── app.js         # 渲染逻辑（原生 JS，无框架）
└── tools/
    ├── verify-ui.mjs      # 用最小 DOM 打桩真实执行 app.js，断言渲染结果
    └── check.mjs          # 静态一致性检查（id / CSS 类 / 标签闭合）
```

## 自检

```powershell
node tools/check.mjs      # 静态一致性（无需启动服务）
node tools/verify-ui.mjs  # 端到端渲染验证（需先 node server.js）
```

## 备注

- 座位数据以校方系统为准，本项目仅作观察与学习用途；选座请前往官方系统。
- 上游接口若调整字段或结构，`/api/status` 中会出现连续失败，此时需要按新结构更新 `src/tsinghua.js` 与 `src/aggregate.js`。
- 如需长期运行，建议把 `server.js` 交给进程守护（如 pm2、Windows 任务计划程序）托管。
